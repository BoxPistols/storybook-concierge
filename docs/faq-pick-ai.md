# FAQの選択を型付き判定に置き換える

## いまの作り

`findFaqAnswer`（`src/ChatSupport/faqDatabase.ts`）は3段構えになっている。

1. 同義語を展開し、キーワードが含まれていれば語の長さを足す。合計が3以上ならそのFAQを返す
2. 届かなければFuse.jsのあいまい検索（threshold 0.6、採用はscore < 0.45）
3. それでも決まらなければ、1で拾った低スコアのものを返す

語が一致しない言い換えに弱く、しきい値が3つある。どれを動かしても、別の質問の結果が変わる。

## 測った結果（2026-09-20、jev-1.13.0）

FAQ 10件に対し、質問を30件用意した。内訳は、各FAQを言い換えて聞いたもの20件（キーワードをそのまま含まない）と、どのFAQでも答えられないもの10件。

| | FAQに当たる20件の正解 | FAQに無い10件に誤って答えた数 |
|---|---|---|
| `findFaqAnswer` | 12 | 1 |
| Jevのchoice | **19** | **0** |

Jevが外した1件は「この相談窓口で何ができるのか教えて」で、confidenceは0.56だった。しきい値を0.6に置くと、この1件は「選べなかった」側に落ちる。

同じ測定を2回続けて回したところ、30件すべて同じ判定だった。confidenceが0.6を下回ったのは2件だけで、残る28件は0.9以上だった。

費用と時間は30件で入力29,062トークン、1件あたり300ms、約$0.0012だった。

正解のラベルは筆者が付けたもので、質問文も筆者が書いた。件数も30件と少ない。導入先のFAQで測り直せるよう、質問と集計のスクリプトの形はこの文書に残す。

## 入れ方

- `api/faq-pick.ts`: サーバー側の口。`TYPESAFE_API_KEY`はここだけが持ち、ブラウザには出さない。返すのはFAQの添字とconfidenceだけで、回答の本文はクライアントが持つFAQから引く
- `src/ChatSupport/faqPick.ts`: 選択肢の組み立てと応答の解釈。confidenceが0.6未満、または受け皿（none）が選ばれたときは「選べなかった」とする
- `src/ChatSupport/hooks/useChatMessage.ts`: FAQで答える経路で、まず判定に聞き、選べなければ既存の`findFaqAnswer`に落ちる

キーが設定されていない環境では、口が501を返し、クライアントは既存のキーワード検索に落ちる。通信が失敗したときも同じで、チャットは止まらない。

## 送るもの

利用者の質問と、FAQの題・キーワードだけを送る。回答の本文は送らない。1つの質問につき1リクエスト。

## 測り直す

```bash
TYPESAFE_API_KEY=... npx tsx tools/measure-faq-pick.mts
```
